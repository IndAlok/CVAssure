## 1. What the builder returns

```python
# cvassure.shift.scenario  (P5)
def build_demo_scenario(seed: int = 42, out_dir: Path | None = None) -> Scenario: ...
```

```python
@dataclass(frozen=True)
class Scenario:
    seed: int
    data_dir: Path  # COCO JSON + images
    model_path: Path  # backdoored or substituted ONNX
    records_path: Path  # JSONL inference records, some tampered
    manifest_path: Path  # THIS file, json

    # convenience accessors, all reading the manifest
    def poisoned_source(self) -> str: ...  # e.g. "C-07"
    def clean_source(self) -> str: ...
    def backdoored_model_path(self) -> Path | None: ...
    def tampered_record_ids(self) -> list[str]: ...
    def replayed_record_ids(self) -> list[str]: ...
    def fog_batches(self) -> list[str]: ...
    def patch_batches(self) -> list[str]: ...
```

**`poisoned_source()` is the authority.** The nightly test reads *this*, not a hard-coded
`"C-07"`. If the builder renames the poisoned contributor, the test follows. That is the whole
point of not hard-coding a contributor id in the assertions.

## 3. Required attack families

Implement in this order. P1 only *names* these in the coverage statement; P1 does not
implement them.

| family | target | notes |
|---|---|---|
| BadNets-style patch | data + model | same `patch_id` on both sides, this is what the LINK line proves |
| blend | data | trigger blended into the image |
| label flip | data | mislabelled samples from one contributor |
| near-duplicate flood | data | many near-identical samples |
| OOD insertion | data | out-of-distribution material |
| model swap | model | a substituted, non-matching model |
| record tamper | records | one record edited after signing |
| record replay | records | one record replayed with a used nonce |
| natural fog | shift | `B-2`, a global shift with no trigger |

**WaNet and imperceptible clean-label perturbations stay `Unsupported` by declaration.** Do
not implement them. The coverage statement says so out loud, which is stronger than a demo
that quietly omits them.

Attack *definitions* may be cited from NIST TrojAI artefacts and BackdoorBench — the PS §7.1
reference clause. **Do not add either repo as a dependency and do not download their
pretrained weights.** Copy the definition, cite the source, generate the pixels yourself.

## 4. Link calibration variants (plan §10.3)

Person 1 needs four scenarios from the same seed family to calibrate `tau_link`. The test
asserts the *expected* column; the linker must not be tuned to force it.

| variant | expected |
|---|---|
| backdoor patch **equals** the data patch | link |
| backdoor patch **differs** from the data patch | no link |
| clean model, poisoned data | no link |
| backdoored model, clean data | no link |

Report link precision and recall over **at least 3 seeds**. That becomes the
`Cross-asset linking` coverage row. The negative controls are the point: a linker that links
everything scores 1.0 recall and is useless.

Expose these as, e.g.:

```python
build_demo_scenario(seed=42, variant="patch-equal")  # default
build_demo_scenario(seed=42, variant="patch-differ")
build_demo_scenario(seed=42, variant="clean-model")
build_demo_scenario(seed=42, variant="clean-data")
```

## 5. The sidecar is not the manifest

`source_id` and `batch_id` reach the day-2 adapters from **extra annotation fields or a
sidecar JSON** that the dataset ships with. That sidecar is a plain mapping and contains no
attack information. It is not this file, and it must not be a symlink or a copy of it.

If the only way to get `source_id` into a sample is to read this manifest, the adapter design
is wrong. Contributors are real metadata about a dataset; attacks are evaluation ground truth.
