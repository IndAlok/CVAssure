# EMBEDDINGS — shared embedding file

**Owner:** Person 2. **Status:** STRAWMAN, day 1. Person 1 wrote it, **Person 2 owns the
encoder and the format.** Person 1 never loads this; it goes straight from you to the
detectors that need it, and nothing else in core depends on it.

---

## 1. Two files, always together

```text
embeddings/
  embeddings.npy     # float32, shape (N, D)
  meta.json          # encoder identity + how row i maps to a sample id
  sample_ids.json    # OR: sample ids inside meta.json as a list
```

Row `i` of `embeddings.npy` is the embedding of `sample_ids[i]`. **That sentence is the
entire contract.** Everything else is metadata so a run can be audited later.

Do not reorder one file without the other. Do not shard. Do not compress. A (N, 512) float32
array for 10 000 samples is 20 MB and that is acceptable; cleverness here buys nothing and
costs an afternoon of debugging.

---

## 2. `meta.json`

```json
{
  "encoder_name": "resnet18-imagenet",
  "encoder_version": "0.4.1",
  "weights_sha256": "9c11e0…",
  "dimension": 512,
  "dtype": "float32",
  "preprocessing": {
    "resize": [224, 224],
    "interpolation": "bilinear",
    "normalise": "imagenet",
    "colour_space": "RGB"
  },
  "sample_count": 10000,
  "sample_ids_file": "sample_ids.json",
  "sample_ids_sha256": "4de0…",
  "synthetic": true,
  "data_licence": "synthetic - generated by this repo",
  "notes": "layer: avgpool, post-ReLU. Not contrastive, not domain-specific."
}
```

| field | why it exists |
|---|---|
| `encoder_name`, `encoder_version` | a number computed with a different encoder is not comparable to one computed with yours |
| `weights_sha256` | the same name can point at different weights tomorrow |
| `dimension` | a shape check, so a mismatched file fails loudly instead of silently |
| `preprocessing` | embeddings from different preprocessing are not comparable, and near-duplicate detection silently degrades when this drifts |
| `sample_ids_sha256` | ties the array to the id list, so a half-copied directory is caught |
| `synthetic` | the PS dataset rule, asserted in the file itself |

`weights_sha256` and the preprocessing block are not decoration. Near-duplicate and OOD
detection are threshold-based, and a changed encoder with an unchanged file name produces
plausible, wrong numbers. That is the failure mode a judge will probe.

---

## 3. Validation the loader should do

Cheap, and each one prevents a silently-wrong result:

1. `embeddings.npy` loads as float32, rank 2, `shape[1] == meta.dimension`
2. `len(sample_ids) == shape[0]`, no duplicates
3. `sha256(sample_ids.json) == meta.sample_ids_sha256`
4. every value is finite — a NaN row means the encoder blew up on one image

Raise on a failure. Do not repair and continue. A partial embedding file is a broken run, and
the honest output is a `data` Finding saying the file did not validate, not a report full of
numbers from the rows that happened to load.

**Do not use `allow_pickle=True`.** Ever, for this file or any model file. A pickled array is
arbitrary code execution on an untrusted artefact, and the pipeline is supposed to be the
trust boundary.

---

## 4. How your detectors get it

`AuditContext` has no embeddings attribute on purpose — most detectors do not need 20 MB, and
loading it for all of them is waste. Instead:

- a `dataset.cache_dir` you own, and
- `configure(cfg)` for the path:

```python
def configure(self, cfg: Mapping[str, Any]) -> None:
    self.embedding_dir = Path(cfg["embedding_dir"])
```

Default it to `""` and skip cleanly when it is empty:

```python
if not self.embedding_dir:
    res.status = "skipped"
    res.skipped_reason = "no embedding_dir in config"
    return res
```

A skipped method with a reason is a correct result. A method that guesses at embeddings and
reports a number is not.

## 5. Out of scope for you and for everyone

- No network. The encoder weights are already on disk or the feature is unavailable.
- No fine-tuning. The baseline assessment does not retrain anything (PS §2.6).
- No torch in `cvassure.core`. If your encoder needs torch, import it inside your own module.
- Do not commit the `.npy` for the demo. Generate it from the scenario; it is derived data.
